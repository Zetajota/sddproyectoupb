# Tareas 001 — MVP web local de GameLog

- **Estado:** planificación; ninguna tarea de implementación iniciada.
- **Base:** [spec v2 aprobada](spec.md), [plan aprobado](plan.md) y [constitución](../../docs/constitution.md).
- **Uso:** ejecutar una tarea a la vez, en este orden. Cada tarea está estimada en **20–30 minutos como máximo**; si excede ese tiempo, dividirla antes de implementarla. Escribir primero las pruebas pertinentes, ejecutar `pytest -q` y marcar la casilla solo cuando se cumpla «Hecho cuando».
- **Convención:** `RF-x.y` es un requisito funcional; `CL-x`, un caso límite. Las tareas de infraestructura indican qué requisitos habilitan, pero solo las pruebas de comportamiento demuestran su cumplimiento.

## A. Base y reglas independientes de la web

- [ ] **T01 — Preparar el proyecto instalable.** Crear `pyproject.toml`, paquete Python y configuración de pytest con versiones compatibles de Python, Flask y pytest. **RF:** habilita RF-1 a RF-4; RNF-5. **Hecho cuando:** la instalación local funciona y `pytest -q` descubre una prueba mínima sin tocar datos reales.
- [ ] **T02 — Crear el esquema SQLite inicial.** Tablas de juegos, tipos y resultados, versión de esquema, restricciones y claves foráneas activas. **RF:** habilita RF-1.1, RF-2.1, RF-3.1; RNF-2, RNF-7. **Hecho cuando:** una prueba en base temporal crea las tablas y rechaza una referencia inexistente.
- [ ] **T03 — Guardar y consultar juegos.** Repositorio SQLite para altas, listados y búsqueda por id, con unicidad de `name_key`. **RF:** RF-1.1, RF-1.2, RF-1.9. **Hecho cuando:** sus pruebas recuperan un juego tras reabrir la base y rechazan duplicados.
- [ ] **T04 — Guardar y consultar tipos.** Repositorio de tipos por juego, unicidad por nombre normalizado y distinción entre predefinidos y propios. **RF:** RF-2.1, RF-2.2, RF-2.3. **Hecho cuando:** las pruebas aíslan los tipos de dos juegos y persisten su dirección.
- [ ] **T05 — Guardar y consultar resultados.** Repositorio de resultados con id estable, valor entero y fecha; consulta por tipo. **RF:** RF-3.1, RF-3.3, RF-4.1. **Hecho cuando:** dos resultados iguales tienen ids distintos y reaparecen tras reabrir la base.
- [ ] **T06 — Probar transacciones y cascadas.** Garantizar borrado relacionado completo y reversión ante un fallo inducido. **RF:** RF-1.6, RF-2.7, RF-3.9; **CL:** CL-11, CL-12, CL-17; RNF-7. **Hecho cuando:** las pruebas comprueban cascadas y que un error conserva todos los datos previos.
- [ ] **T07 — Normalizar y validar nombres.** Funciones puras para NFC, espacios extremos, `casefold`, controles, longitud y alias `Score`. **RF:** RF-1.1, RF-1.4, RF-2.2, RF-2.5; **CL:** CL-9, CL-16. **Hecho cuando:** pruebas de nombres válidos, duplicados y límites pasan sin Flask ni SQLite.
- [ ] **T08 — Analizar puntuaciones y valores propios.** Convertir entradas válidas a enteros exactos y rechazar signos, comas, exponentes y exceso de cifras. **RF:** RF-3.5, RF-3.6, RF-3.7; **CL:** CL-8, CL-20. **Hecho cuando:** las pruebas cubren cero, ceros iniciales, dos decimales y entradas inválidas.
- [ ] **T09 — Analizar y mostrar tiempos.** Convertir `mm:ss.cc` a centésimas y de vuelta, con límites exactos. **RF:** RF-3.4, RF-3.7; **CL:** CL-7, CL-20. **Hecho cuando:** `03:42.58` equivale a 22258 centésimas y los formatos fuera de rango fallan.
- [ ] **T10 — Calcular el mejor resultado.** Función pura para máximo, mínimo y estado sin récord. **RF:** RF-4.2, RF-4.3, RF-4.4; **CL:** CL-1, CL-4, CL-5, CL-14, CL-15, CL-21. **Hecho cuando:** las pruebas demuestran aislamiento por tipo y recálculo tras cambiar los datos recibidos.
- [ ] **T11 — Ordenar el historial.** Mejor marca, más antiguo y más nuevo, con desempates por id original. **RF:** RF-4.1, RF-4.5; **CL:** CL-2, CL-13, CL-18. **Hecho cuando:** las pruebas cubren ambas direcciones y empates de valor y fecha.

- [ ] **T13 — Consultar juegos y su ficha.** Caso de uso de lista y detalle, incluidos estados vacíos e id inexistente. **RF:** RF-1.2, RF-1.9, RF-2.3, RF-4.4; **CL:** CL-1. **Hecho cuando:** las pruebas muestran juegos separados y error para un id inexistente.
- [ ] **T14 — Renombrar juegos.** Caso de uso que mantiene tipos y resultados, con validación de duplicados. **RF:** RF-1.4, RF-1.5, RF-1.8; **CL:** CL-9. **Hecho cuando:** las pruebas confirman asociaciones intactas y ningún cambio en un error.
- [ ] **T15 — Borrar juegos.** Caso de uso que distingue confirmación y cancelación y borra en cascada. **RF:** RF-1.6, RF-1.7, RF-1.8; **CL:** CL-11, CL-17. **Hecho cuando:** borrar elimina solo el juego elegido y cancelar conserva sus datos.
- [ ] **T16 — Crear y consultar tipos propios.** Caso de uso para nombre y dirección por juego, con alias reservado. **RF:** RF-2.2, RF-2.3, RF-2.5, RF-2.11; **CL:** CL-4, CL-9, CL-16. **Hecho cuando:** las pruebas aceptan alta y baja dirección y rechazan `Score` y duplicados.
- [ ] **T17 — Editar tipos propios.** Cambiar nombre o dirección, manteniendo resultados y prohibiendo los predefinidos. **RF:** RF-2.5, RF-2.6, RF-2.8, RF-2.10; **CL:** CL-10, CL-15. **Hecho cuando:** las pruebas conservan la asociación y obtienen un nuevo récord al invertir dirección.
- [ ] **T18 — Borrar tipos propios.** Confirmación, cancelación, cascada y rechazo de tipos predefinidos o inexistentes. **RF:** RF-2.7, RF-2.8, RF-2.9, RF-2.10; **CL:** CL-10, CL-12. **Hecho cuando:** las pruebas conservan los otros tipos y sus resultados en todos los caminos.
- [ ] **T19 — Registrar resultados con reloj inyectable.** Validar juego, pertenencia del tipo y valor antes de leer una vez la fecha local y guardar. **RF:** RF-1.3, RF-2.4, RF-3.1 a RF-3.7; **CL:** CL-3, CL-6 a CL-8, CL-19, CL-20. **Hecho cuando:** pruebas con reloj falso comprueban fecha única y cero escrituras en entradas inválidas.
- [ ] **T20 — Editar solo el valor del resultado.** Validar según su tipo y conservar id, juego, tipo y fecha. **RF:** RF-3.8, RF-3.10; **CL:** CL-21. **Hecho cuando:** las pruebas demuestran que una edición inválida conserva el resultado anterior.
- [ ] **T21 — Borrar un resultado.** Quitar solo la entrada elegida y permitir registrar otra después. **RF:** RF-3.9, RF-3.10; **CL:** CL-14. **Hecho cuando:** las pruebas confirman el siguiente récord o el estado vacío y el error ante id inexistente.
- [ ] **T22 — Consultar historial y récord por tipo.** Reunir resultados, dirección, mejor marca y orden elegido sin mezclar juegos ni tipos. **RF:** RF-2.11, RF-3.11, RF-4.1 a RF-4.5; **CL:** CL-1 a CL-5, CL-13 a CL-15, CL-18. **Hecho cuando:** pruebas de servicio devuelven ids, fechas y valores correctos para los tres órdenes.
